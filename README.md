# Wise Motion

先结合上下文理解用户意图，转译为画面变化、动作关系与约束，再匹配本地动效，通过设计、改良、发散和随机组合形成方案。按请求交付参考说明、静态画布、可播放动效或视频。新动效及新视频中的动效统一使用 Remotion；目录界面、静态画布和普通网页不受此限制。维护已有非 Remotion 工程时保留原栈，不自动迁移。

设计与源码选择见 [导演设计方法](references/director-design.md)，逐个开发与整合见 [阶段制作方法](references/pipeline-methodology.md)。

明确调用 `$wise-motion`，从 [SKILL.md](SKILL.md) 的“先确定交付”开始，按请求选择参考、方案、静态画布或动效制作。需要新建分镜计划时再执行五步流程；已有故事板与时间表继续沿用。

标准动作在有第三方来源时显示“来源”：有明确授权的代码改编写“AI 改编自……的代码”，明确的第三方效果参考写“效果参考……”。已迁入条目的原作出处与抽取范围保留在来源说明和私有历史记录中。本地自有内容不展示自行开发声明，也不把使用动画库误写成动作来源。动画库及项目许可保留在版权与来源文档中。

预览保持 16:9，桌面同时按剩余高度限制画板尺寸。播放条材质接入 [Deepika 的开源背景折射](https://github.com/deepika-builds/liquid-glass)，源码和 MIT 许可随包保留。Chrome 等 Chromium 浏览器使用边缘折射，Safari、Firefox 保留磨砂回退。播放条采用紧凑的两行圆角面板：上方为两端时间和中性进度条，下方为居中的播放／暂停大按钮，重播和全屏放在两侧。桌面端面板浮在预览下沿之内，整条都压在画面上，边缘才有内容可弯；窄屏改为落在画面下方，避开本来就小的动效。两侧内容独立滚动，菜单按可用空间向上或向下展开。窄屏目录打开时限制背景交互，支持 Escape 关闭和焦点回到打开按钮。触屏主要按钮提供 44 像素的操作区域。

目录保留原面板比例与控件层次，普通示例的视觉统一参照本机展示片 56 秒的时间线：近黑底、暖白文字与细线，橙、紫、青等节点色只作必要强调；静态轻颗粒与暗角不增加播放开销。白天使用暖浅底，保持色相并调整对比。螺旋丸、牛皮纸等插画保留原配色与材质，不叠普通场景的纹理。普通结构示例的纯英文和纯数字统一使用本地 Oswald Bold，苹果空间卡片采用系统无衬线文字，中文正文和辅助标签使用思源黑体 Light，动效内中文主标题、分类与章节标题允许使用思源黑体 Bold。画板字号统一为 12、16、24、32、48、64 像素，细密刻度用 10 像素；图形缩放后按实际画板大小补偿。字形造型、词云和连续缩放的动作保留大小关系。单个动作按入场、文字、数据、扫描、布局、滚动、路径、回弹、形变、立体、强调、光效、反馈、粒子和转场分组。插画素材按自然与天体、流场与能量、几何与网络、物件与角色、界面与读数分组；组合片段按文字与叙事、界面与演示、图形与材质分组。每个条目按主要用途归入一组，分类筛选只展示当前页签的分组。历史来源记录保留原工程字体、字号及素材关系，不作为当前页面入口。

名称用简短中文说明可复用的动作，通常为四到八个字。例如“斜升回正”说明进入与姿态变化，“双排反向滚动”和“双排反向停靠”区分循环与落定，“匀速缓动对照”说明速度差异，“文字汇聚光核扩散”说明组合的先后关系。动作名称不绑定手机、年份、片名或提示词等示例内容；插画名称直接说明图形或物件，具体示例和来源保留在说明中。分类以主要用途和变化为准：数据图表与扫描信号分开，重点强调与光效氛围分开，粒子释放和拖尾归粒子与流动；单画面的布局调整不归入画面转场。旧名称保留为搜索词；目录标题、复制内容和说明文档使用统一的新名称，原有链接与源码入口保持稳定。

播放条试用 iOS 26 液态玻璃的网页材质近似：直接使用开源脚本的默认位移（边缘鼓起、三通道色散、中心磨砂），外观沿用其示例的薄渐变底、上缘高光、内缘反光、一像素玻璃边和投影，左上留一团静止反光。深浅外观只改这层薄着色。主播放键是面板上唯一常驻的圆形芯片，重播和全屏静止时是比播放键小的白色字形，悬停才浮起小玻璃。材质参考 [Apple 官方材质与浮动导航演示](https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/)，两行布局与浮动位置参考用户提供的 iOS 锁屏播放器截图和 Apple Music 浮动导航。播放条透出当前主题的画面底色。这是网页背景折射的近似，未实现苹果原生自动背景识别与连续形变；其他面板保持原外观。浏览器不支持背景模糊，或开启增强对比、支持的降低透明度设置时，播放条回到实色。本次主题更新未进行浏览器截图验收，实际外观按验收步骤复核。

保留苹果人机交互指南中适用于网页的键盘焦点和外观显示设置，设计依据与适用边界见 [界面设计说明](references/apple-hig.md)。侧栏主题按钮只在深色和浅色之间切换，默认深色；支持增强对比。选择动作、插画或组合时，中央预览默认从头自动播放；相关动作弹窗和复制保存的页面也从头播放，不依系统动效偏好降级或暂停，不显示相关提示或开关。手动暂停与时间定位保持有效；目录页面隐藏时暂停，返回后只恢复隐藏前正在播放的内容。列表用各自场景的静态缩略图，窗口变化后重新计算尺寸，不创建动画实例；切换动作释放旧实例。自编源码、字体、Remotion 播放器与固定版本 Anime.js 全部在本地，Anime.js 保留原缓动计算。

插画素材保留自身动作。当前 61 个插画中，60 个带动作；斜放手机的空屏机身保持静态。右栏“插画包含的动作”可直接打开对应动作。相同运动方式优先归入已有动作并增加插画示例；缺少的动作独立登记并共用实际绘制。雨伞关联原六段动作，月亮沿用光面渐满；玻璃卡、汽车、太阳和种子复用已有动作，冠毛展开转向与长条扫过独立纳入。

25 个组合均可逐层查看真实画面组成。右栏“相关动作”直接打开已登记的单个动作弹窗，并从头自动播放；主组合、播放位置、拆解选择和筛选保持不变。弹窗打开时暂停主画面，关闭后恢复此前的播放状态并释放弹窗播放器。

拆解顺序：先保留组合原画面，按实际对象与绘制代码拆出子动作，再对照动作库查重。几何、运动规则和时序机制真正一致才复用；缺少的独立动作与组合共用绘制函数，只创建自身需要的对象，不以整段组合隐藏其它图层代替拆解。双排反向滚动、双排滚动减速停靠和弧面卡片轮播作为普通动作。

新增的“笔墨与材质演变”保留精修后的纸底、书法、点线柱体、材质重组、球体、图鉴与字标收尾；七段也可单独播放；完整组合统一从 [正式目录](catalog/index.html) 打开。较大的字形数据和图片选中后才准备，静态缩略图只画代表时刻。原视频和截图不进入目录；字形轮廓与生成素材的权利说明见版权记录。

“玻璃卡片显现折射”统一采用苹果空间界面，保留黑银玻璃材质与7.2秒完整组合。六张卡分别是 Siri、短信、系统设置、音乐、天气和控制中心；Siri 显示监听波形与播放音乐指令，短信包含联系人、时间、左右消息气泡和输入栏，系统设置使用勿扰开关与亮度滑杆。卡内文字使用系统无衬线字体和自然大小写，界面参考统一为 [Apple Vision Pro 空间界面](https://www.apple.com/newsroom/2023/06/introducing-apple-vision-pro/)，玻璃材质补充参考 Apple 液态玻璃设计。六张卡使用三轴旋转、透视投影、十像素圆角侧壁与随朝向移动的反光；音乐、天气和控制中心按0.85秒间隔来到前景，封面涟漪、播放进度、亮度与音量随时间变化。短信卡再次来到前景后，四条日常回复依次逐字出现，凸泡采样实际画面、放大短信文字，并在 MOTION 第一个 O 的中心淡出。片尾字标沿用 Helvetica Neue Bold 原生字形与字距，双语短句随后出现。背景、卡面、侧壁和控件保持黑白灰，凸泡无深色内圈与整圈描边。六张独立插画保留相同空间运动和卡内变化，卡外透明；完整组合、独立动作、目录预览、复制要求和导出共用绘制源码与统一定义。

“目标扫描捕获锁定”保留原版五层环圈、细线仪表与数据读数：初始采用更多银白主线与纯白高光，锁定后变为红色；开头保留原有地球地图，最后推近并定格于地中海、意大利一带；锁定采用狙击镜式准星，主状态显示“锁定目标”，卡面内容留出内边距，接收强度与遥测仪表采用完整闭框；两侧数据图更新为面积趋势、三组弧形仪表、轨迹定位、通道占比分区和回波热力，其余文案更新为“星巡”观测主题，背景为中性近黑。完整组合和十一个独立动作共用绘制源码；来源与数值依据见[说明](references/hud-targeting-source.md)。

“金属弹开汇聚成字”落地后六球沿高低、左右、前后不同方向大幅散开，再用0.76秒从各自位置沿弧线直接汇向中心；中心短促压聚后向四周散射六色金属粒子，再由同一批粒子回收到字面，在收拢末段形成光滑 MOTION，最后扫光。“落地分裂六球回弹”“中心汇聚散射成字”“抛光金属字面扫光”可分别预览和复制。完整组合为 5.3 秒，两个 O 为圆形；无需原演示或视频素材。

## 技能入口与选型

全局使用时，将 `~/.agents/skills/wise-motion` 直接链接到技能的实际源码目录。Cursor 和 DeepSeek Harness 默认读取这个共享目录；Codex 的 `~/.codex/skills/wise-motion` 与 ZCode 的 `~/.zcode/skills/wise-motion` 同样直连源码。各入口共用同一份技能与资料。

在任意项目从工具的技能列表明确选择 Wise Motion；Codex 可用 `$wise-motion`，Cursor 可用 `/wise-motion`。正文的 `disable-model-invocation: true` 与 Codex 入口的 `allow_implicit_invocation: false` 保持手动调用。新增入口后刷新技能列表或新开会话。检索、查看与分镜命令可通过全局入口的绝对路径执行，分镜计划和装配结果应写入目标工程。

检索前先形成简短需求转译，明确表达目的、主体的前后状态、动作关系、节奏与约束。简单请求可以在回复中说明，已有故事板就记在对应段落，不增加固定确认步骤。随后将转译后的动作描述交给本地辅助检索，无需安装依赖：

```sh
node scripts/match.mjs "两排卡片反向持续滚动，不要轮播，不要停顿"
node scripts/match.mjs "卡片从下方轻轻上移并淡入，减速落定后保留，不要弹跳"
node scripts/match.mjs "六张卡片依次放大显现，落位后保留" --limit 3
node scripts/match.mjs "抛光金属字面扫光" --details
```

默认列出前五个候选，也可用 `--limit 3` 限制数量；每项给出匹配理由、画面说明、源码路径和详细说明入口，`--details` 展开完整动作说明。候选可能只覆盖需求的一部分；字幕、主体动作、材质和转场应分别检索后核对组合关系。

需求理解与转译由 AI 先完成，词语匹配只辅助搜索；候选还须回到原话与上下文，核对目的、关系、因果和节奏，不能因名称命中或排名靠前就直接采用。现有动效都是参考：有匹配也可改良，没有匹配也可发散；可以跨类别随机组合，再按表达与可读性筛选。采用方案记录在动作计划，播放与导出不重新随机。只在确需外部依据或用户要求时定向联网。

选出候选后，用 `show.mjs` 查看画面说明、源码与依赖大小、变体、可调节奏、权利和可粘贴的 Remotion 片段，并阅读实际源码。新建字幕或多镜头视频工程时，用 `plan.mjs` 生成并检查计划，再装配成 Remotion 工程；只要参考或方案时交付选择理由和路径。制作步骤与速选表见 [快速上手](references/quickstart.md)，示例计划见 [plan-example.json](references/plan-example.json)：

```sh
node scripts/show.mjs word-slam
node scripts/plan.mjs init 字幕.txt ~/video/plan.json
node scripts/plan.mjs check ~/video/plan.json
node scripts/plan.mjs build ~/video/plan.json ~/video/src/index.jsx
```

`check` 会拦截空白设计字段、没读源码就采用（`effect.source` 对不上）、插画当动作、微调和原创缺少提示词、镜头短到动作被截断等问题，并提醒阅读时间不足和同一动效重复使用；`build` 在检查未通过时拒绝装配，帧数与速度由计划推出，不手写。计划和装配文件属于视频工程，脚本拒绝写进技能目录。

在 wise-video 项目可调用 `$wise-motion`。参考目录的展示规则见 [目录维护](references/catalog-maintenance.md)，新作品按自己的设计方向制作。

技能与加载入口检查：

```sh
python3 scripts/verify_project_skills.py --repo-root .
python3 scripts/verify_project_skills.py --repo-root /Users/wisewong/Documents/Developer/wise-video
```

## 修改与验证

标准动作的权威定义是 `catalog/registry.json`。日常构建生成页面数据、标准说明和播放器，不读取或改写源码外的历史档案。历史审查的权威记录位于私有状态目录 `../../state/wise-motion/history/`；只有修改这些记录时才运行 `npm run build:history`，用 `npm run check:history` 核对。生成文件不手工维护。

```sh
npm ci
npm run build
npm test
npm run render -- stagger-in stagger-in.mp4
```

构建使用固定版本的 React、Remotion 和打包工具；`npm run build` 同时生成目录数据、组件和本地播放器。`npm run check` 检查结构与字体覆盖；`npm test` 另含原作迁移与绘制公式检查，需要保留私有历史档案。实际浏览器与视频检查另行进行。目录本身仍可直接打开，无需安装依赖或启动服务。视频导出会使用 Remotion 临时服务。

制作与导出的 Node 版本遵循 `package.json`（当前为 `^24.15.0 || >=26`）。检索命令无需安装视频依赖；独立复用须按复制源码的说明安装依赖与 `public/wise-motion` 素材，不能只复制绘制入口就期待直接渲染。

自动检查覆盖字段、组合与历史对应关系、案例级源码路径、生成文件一致性、静态资源本地化、匹配差异、全部标准示例的反复定位，以及异步原作加载、案例切换、播放接口和资源释放。保留目录抽屉、菜单、键盘与缩略图检查。自动检查不代替真实浏览器体验，人工体验按 [验收步骤](tests/manual.md) 直开完成。

实时预览只在首次准备及新素材尚未就绪时等待，无声目录不初始化音频播放；普通绘制由 Remotion 时钟推进，视频导出仍等待每一帧及画面提交完成。胶囊、绿洲及流线复用固定几何、字宽和绘图数据，保持原画幅、细节数量与运动公式。

预览按条目加载原绘制文件及其声明的依赖，组合按原顺序加载相关绘制；缩略图绘制失败会明确显示原因。

目录首屏不再同步解析最大的几份数据：文明聚字、螺旋丸插画、文明生长的绘制文件由 `catalog/lazy.js` 按需载入；完整源码索引仅在打开需要它的代码页签时载入，浏览动效和复制提示词不触发。缩略图以侧栏滚动区为观察范围，在上下各 320 像素内提前准备。载入失败显示原因并可重试，准备期间禁用代码复制。此前移除同步大文件时，本机真实 Chrome 测得首屏解析完成约 480 毫秒降到 375 毫秒，初始内存约 93 MB 降到 38 MB；各条目的绘制代码与运动公式没有改动。新增体积较大的数据文件时，把它登记到 `lazy.js` 的 `EFFECT_FILES`，不要写回 `index.html`。需要全量核对真实实现和依赖时，运行 `node scripts/audit-catalog.mjs --output ../../maintenance/wise-motion-performance/current.json`。检查使用 Remotion 配套浏览器直接打开本地文件，不启动服务、不截图，覆盖全部条目与变体的实际绘制、重复定位、加载前后画面数据、复制代码及打包素材。它不代替完整动画的人工观看。

本地字体保留思源黑体和霞鹜文楷的原始名称、完整字符与字体数据，仅压缩为网页格式，原 OFL 许可随包提供。需要重新导出时运行 `python3 scripts/build-fonts.py`；导出需要本机原字体和 FontTools。`npm run check:fonts` 核对原字体名称及目录汉字覆盖，日常检查只读取随包字体，不读取本机原字体。界面正文及列表名称使用细体，品牌、当前动作标题和章节标题保留粗体。
