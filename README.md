# Wise Motion

理解动作需求，拆解并匹配参考，交付现有源码与接入说明。字幕、分镜、配色和整片组合由调用方的 AI 自行设计；文字动效、转场、插画和组合均可按需取用。

Understand a motion request, break it down, find matching references, and deliver existing source code with integration guidance. The AI using this skill designs captions, storyboards, colors, and the overall video; text animations, transitions, illustrations, and sequences are available to reuse as needed.

## 浏览与使用 / Browse and use

直接打开 [动效目录](catalog/index.html)，无需安装依赖或启动服务器。搜索覆盖全部动作、组合和插画，不受当前页签或分类限制；清空搜索后回到当前页签浏览。选择条目后可预览、调整参数，再复制提示词或源码。

Open the [motion catalog](catalog/index.html) directly from your local files; no dependency installation or server is needed. Search covers all motions, sequences, and illustrations, regardless of the active tab or category. Clearing the search returns you to the active tab. Select an entry to preview it, adjust its parameters, and copy its prompt or source code.

在工具中明确选择 **Wise Motion**，例如：

Explicitly select **Wise Motion** in your AI tool, for example:

```text
$wise-motion 找两排卡片反向持续滚动的参考，不要停顿，导出源码到我的工程。
$wise-motion 找“标题先出现、卡片依次展开、最后转场”的参考，分别说明覆盖与缺口。
```

```text
$wise-motion Find a reference for two rows of cards scrolling continuously in opposite directions without pauses, and export the source code into my project.
$wise-motion Find references for a title appearing first, cards unfolding one by one, and a final transition. Explain what each reference covers and what is missing.
```

全局入口直接链接到技能实际源码：共享入口 `~/.agents/skills/wise-motion`，Codex 入口 `~/.codex/skills/wise-motion`，ZCode 入口 `~/.zcode/skills/wise-motion`。保持仅手动调用；已有入口先核对指向。

Global skill entries should link directly to the actual source directory: `~/.agents/skills/wise-motion` for shared use, `~/.codex/skills/wise-motion` for Codex, and `~/.zcode/skills/wise-motion` for ZCode. Keep invocation manual, and check where an existing entry points before changing it.

目录界面和所链接的详细资料目前以中文为主。

The catalog interface and linked detailed guides are currently primarily in Chinese.

## 检索与源码导出 / Search and export source code

以下用 `<skill-directory>` 表示安装入口解析后的实际技能目录；输出路径请替换为自己的目标工程目录。这些命令可从任意工作目录运行。检索、查看、导出只需 Node.js；版本要求见 [package.json](package.json)。

Replace `<skill-directory>` with the actual directory resolved from your skill entry, and replace the output path with a directory in your own project. These commands work from any working directory. Searching, inspecting, and exporting require only Node.js; see [package.json](package.json) for the supported versions.

```sh
node "<skill-directory>/scripts/match.mjs" "卡片依次上移显现，落位后保留，不要弹跳"
node "<skill-directory>/scripts/show.mjs" stagger-in
node "<skill-directory>/scripts/export.mjs" stagger-in --out-dir "/path/to/project/card-motion"
```

检索示例的含义是“卡片依次向上进入并留在原位，不要弹跳”；命令行检索词与中文目录匹配，可由调用方的 AI 将英文需求转换为中文检索词。

The search example means “cards enter upward one by one and stay in place, without bouncing.” Command-line queries match the Chinese catalog; the AI using this skill can translate an English request into Chinese search terms.

`show` 默认提供简短接入信息，加 `--details` 查看动作阶段与内容限制。`export` 支持 `--variant <variant-id>`，与目录“复制源码”共用生成逻辑；可写入现有目录，任一目标文件已存在时整批停止，不覆盖文件。

`show` returns concise integration guidance by default; add `--details` for motion phases and content constraints. `export` accepts `--variant <variant-id>` and uses the same generation logic as the catalog's “复制源码” (Copy source) action. It can write into an existing directory, but stops the entire export if any destination file already exists; it never overwrites files.

已有独立工程的条目导出全部工程文件；普通条目导出组件接入示例、安装程序和说明，在目标工程运行 `node install-wise-motion.cjs` 安装共享组件包，再按说明准备素材。安装程序优先使用当前交付版本；尚未上架时自动降级为同系列最近的已发布稳定版，显示并固定实际版本，配套依赖随所选包安装。导出本身不会安装依赖，源码写入文件后返回绝对路径。见 [快速上手](references/quickstart.md) 和 [组件说明](REMOTION.md)。

Entries with standalone projects export all project files. Other entries export a component integration example, an installer, and instructions. Run `node install-wise-motion.cjs` in the destination project to install the shared component package, then prepare the assets as instructed. The installer prefers the version delivered with the export; if it is not yet published, it falls back to the latest published stable version in the same release series, displays and pins the selected version, and installs its companion dependencies. Exporting itself does not install dependencies and returns absolute paths after writing the files. See the [quick start](references/quickstart.md) and [component guide](REMOTION.md).

## 播放与渲染 / Playback and rendering

现有播放器、声音、渲染能力继续保留。需要导出单个动效视频时，在技能目录准备依赖后执行：

Playback, audio, and rendering remain available. To render an individual motion as a video, install the dependencies and run these commands in the skill directory, replacing the output directory with your own:

```sh
npm ci
npm run build
WISE_MOTION_RENDER_DIR="/path/to/project/renders" npm run render -- stagger-in stagger-in.mp4
```

视频渲染使用 Remotion 临时服务；本地目录可直接打开。文件名或绝对输出路径必须位于指定产物目录内。

Video rendering uses a temporary Remotion server; browsing the local catalog does not require one. The output filename or absolute output path must stay within the designated render directory.

维护时按 [验证范围与命令](references/validation-matrix.md) 选择检查；局部测试统一使用 `npm run test:files -- tests/<test-name>.test.mjs`，将占位符替换为实际测试文件名。全量 `npm test` 另需本地私有历史档案。人工播放见 [验收步骤](tests/manual.md)，目录维护见 [维护说明](references/catalog-maintenance.md)。

For maintenance, choose checks from the [validation matrix](references/validation-matrix.md). Run selected tests with `npm run test:files -- tests/<test-name>.test.mjs`, replacing the placeholder with the actual test filename. The full `npm test` suite also requires local private historical archives. See the [manual playback checks](tests/manual.md) and [catalog maintenance guide](references/catalog-maintenance.md).

维护者可通过 GitHub 可信发布自动构建并上传 npm，无需长期发包密钥；支持版本标签触发和手动试运行，见 [自动发布说明](references/publishing.md)。

Maintainers can use npm trusted publishing through GitHub Actions to build and publish without a long-lived publishing token. Version tags trigger releases, and manual dry runs are supported; see the [automated publishing guide](references/publishing.md).

## 发布组件包 / Publish the component package

维护者先构建、检查并用 `npm pack --pack-destination /path/to/releases` 生成包，将发布目录和版本占位符替换为实际值，再执行：

Maintainers should first build, validate, and create a package with `npm pack --pack-destination /path/to/releases`. Replace the release directory and version placeholder with the actual values, then run:

```sh
npm run publish:package -- /path/to/releases/wise-motion-<version>.tgz --dry-run
npm run publish:package -- /path/to/releases/wise-motion-<version>.tgz
```

发布脚本使用当前 npm 11 客户端向官方仓库发布，保留正常登录与网页身份验证，并压缩上传请求；仅压缩请求仍可能被仓库拒绝，必须控制实际发布包体积。三维制作原件与剪辑原媒体按清单单独准备，运行素材继续随 npm 提供。脚本要求包名称和版本与当前项目一致，并在联网前拒绝超过项目 200 MB 预算的包；这是项目控制体积的约定，不是 npm 官方限制。升级 npm 大版本后需先适配接口并运行 `npm run test:publish`，验证真实请求的压缩和包内容。试运行不会上架，正式发布仍需核对官方仓库的版本与包摘要。

The publishing script uses the current npm 11 client to publish to the official registry, preserves normal login and browser authentication, and compresses the upload request. Compression alone does not guarantee acceptance; the actual package size must stay under control. Original 3D production files and editing media are prepared separately according to their manifests, while runtime assets remain available through npm. The script requires the package name and version to match the current project and rejects packages over the project's 200 MB budget before connecting to the registry. This is a project budget, not an official npm limit. Before upgrading to a new npm major version, adapt the integration and run `npm run test:publish` to verify request compression and package contents. A dry run does not publish anything; after a real release, verify the version and package integrity against the official registry.
