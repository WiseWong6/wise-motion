# 快速上手

给不确定该怎么做的 AI。照做即可得到可用的动效；需要更细的判断时再读 [导演设计方法](director-design.md)。

## 五步

1. **切镜头。** 把字幕存成文本文件，运行
   `node scripts/plan.mjs init 字幕.txt <你的工程>/plan.json`。每行或每句先成为一镜，并给出暂定秒数；这只是草稿，按意思把短句合并、把长句拆开。
2. **逐镜写清变化。** 打开 `plan.json`，每镜填六项：`subject` 看谁、`from` 起始状态、`to` 结束状态、`meaning` 观众理解什么、`hold` 停留多久并看清什么、`handoff` 怎样交给下一镜。写不出来就说明这一镜还没想清楚，不要进入下一步。
3. **选动效。** 先看下面的“按镜头用途速选”，再用
   `node scripts/match.mjs "起始状态到结束状态的动作描述"` 补充候选，用
   `node scripts/show.mjs <id>` 查看细节并**打开列出的源码**。然后在该镜的 `effect` 里选一种：
   - `reuse`：用途、动作阶段都对，直接用；
   - `tweak`：结构对但对象、颜色或节奏要改；先在 `effect.prompt` 写清改什么，再改代码；
   - `original`：没有合适的；先在 `effect.prompt` 写清对象、起止状态、方向和节奏，再实现。
   动效自带的文字、数字和图标是示例内容，组件没有“改文字”的参数；镜头需要你自己的字幕、名称或数据时选 `tweak`，并按下面“换成自己的内容”操作。只有图形、素材、背景、转场这类内容本来合用的才选 `reuse`。
   `effect.source` 必须照抄 `show.mjs` 给出的“路径#入口”，用来证明你确实看过。
4. **检查。** `node scripts/plan.mjs check plan.json`。有“错误”就改到通过；“提醒”要逐条判断是否接受。
5. **装配。** `node scripts/plan.mjs build plan.json <你的工程>/src/index.jsx`，再按 [Remotion 说明](../REMOTION.md) 安装依赖和素材并渲染。原创镜头会留黑底占位，逐个做完再整合；每做完一个先自己看过，再做下一个。

## 换成自己的内容

1. 在目标工程执行 `node node_modules/wise-motion-remotion/scripts/install-assets.mjs public/wise-motion`，素材会复制进工程。
2. 打开 `show.mjs` 列出的源码在工程里的副本（例如 `public/wise-motion/catalog/effects/word-slam.js`），找到示例文字或数据（常见是文件顶部的数组或字符串），改成你的内容。副本只影响这个工程，技能源码不会变。
3. 同一个文件里的其他动效、同一个动效的其他镜头会一起变；两个镜头要不同文字时，要分别拆开处理，不要互相覆盖。
4. 目录自带字体只覆盖目录里出现过的汉字；新增汉字可能回退到系统字体，字形不一致时参考 [README](../README.md) 的补字说明或改用已覆盖的字。
5. 改完重新渲染并看一帧确认文字、位置和停留，再继续下一镜。`build` 会把所有 `tweak` 镜头列为“待改”，直到你自己确认完成。

[完整示例](plan-example.json)可以直接复制改写。

## 硬规则

- **不凭名字选动效。** 名字相似、检索排第一都不算理由；以 `show.mjs` 的动作阶段和源码为准。
- **一镜只有一个主角。** 同一时刻只让一个东西最醒目，其余配合它。
- **不把静态内容套一层缩放、摇摆就算动效。** 内容本身要发生可描述的状态变化。
- **先写提示词，再改代码。** 微调和原创都是；事后补写不算。
- **不写“更高级”“更丝滑”。** 提示词只写能看到的东西，见下面的模板。
- **不确定就按最简单的做。** 硬切、淡入上移已经能完成大多数镜头。
- **如实报告。** 没渲染就说没渲染，没亲眼看过就说只做了脚本检查。

## 按镜头用途速选

下面都是目录里成熟、可直接用的条目，时长为默认值，装配时会按镜头自动调速（0.5 至 2 倍）。

| 镜头要做的事 | 首选 | 备选 |
| --- | --- | --- |
| 开场金句、大字 | `word-slam` 文字撞入换位 | `type-reveal` 文字逐字显现、`particle-word` 粒子聚散成字 |
| 标题加内容 | `title-content` 标题内容展开 | `title-stagger` 标题依次呈现、`fade-rise` 淡入上移 |
| 几项内容依次出现 | `stagger-in` 错峰入场 | `group-expand` 卡片逐张放大、`material-card-stagger` 错峰升入回弹 |
| 强调一个词 | `word-focus` 词语划线强调 | `dim-focus` 周围淡化聚焦、`focus-zoom` 放大聚焦 |
| 数字与对比 | `count-up` 读数递增 | `bar-growth` 柱条依次长高、`benchmark-columns` 数据分栏对比 |
| 展示代码或提示词 | `terminal-code` 代码逐行输入 | `glyph-code-fill` 字形内文字流动、`live-code-readout` 代码参数联动 |
| 零散的东西收到一起 | `motifs-gather-atlas` 缩拢收入群像 | `line-converge` 连线汇聚、`card-compress-merge` 卡片压缩合并 |
| 步骤与流程 | `staged-build` 内容逐层累积 | `experience-progress` 卡片逐项聚焦、`timeline-progress` 时间轴依次点亮 |
| 演示界面操作 | `interface-feedback` 按钮操作反馈 | `button-press-status` 按钮按压换态 |
| 切到下一段 | `wipe` 画面擦入切换 | `shared-object` 同一主体跨场、`zoom-transition` 缩放穿越转场、`page-cover` 新页推入覆盖 |
| 结尾字标 | `seed-bloom-brand-sequence` 生长化蝶与光形字标 | `outro-credit-lift` 文字分层升入、`particle-word` 粒子聚散成字 |

## 好动效的底线

这些是经验起点，内容需要时可以突破，但要在 `effect.prompt` 或 `hold` 里说明理由。

1. **读得完。** 字幕按每秒约 6 个汉字加 0.3 秒估算最短时长，`check` 会提醒不够的镜头；有配音以实测词点为准。
2. **看得清再动下一个。** 结果出现后留一小段停留，再交给下一镜；不要一个动作还没落稳就开始下一个。
3. **入场减速，离场加速。** 默认用末尾减速的曲线；匀速只用于持续滚动、旋转这类循环。
4. **错峰要有规律。** 同组对象依次出现时间隔保持一致，经验值约 0.08 至 0.15 秒；全部同时出现等于没有顺序。
5. **颜色克制。** 一镜以黑白灰为底，最多再加一个强调色；材质类条目（金属、玻璃、纸）保留各自配色，不要再叠滤镜。
6. **字号成档。** 目录画板为 640×360，字号取 12、16、24、32、48、64；正文不低于 16，放进更大画幅时等比放大，不临时发明字号。
7. **同一个动效最多连用两次。** 想重复就换同类的另一个，或改变方向与节奏。
8. **转场只用在语义换段。** 同一段内部用硬切；复杂转场不要遮住上一镜的结果。
9. **改了就重新生成。** 改 `plan.json` 后重新 `build`，不要手改生成文件里的帧数。

## 提示词模板

微调和原创必须在改代码前写成这样，每一项都要有具体内容：

```
对象与构图：<谁、在画面哪里、多大>
起始状态：<动作开始前看到什么>
推进：<先发生什么，再发生什么；方向、距离、顺序>
落点：<停在哪里，保留什么>
节奏：<总时长；哪一段快，哪一段慢；错峰间隔>
保持不变：<沿用原条目的哪些部分>
避免：<不能出现的跳变、遮挡、同时抢焦点>
```

## 常见失误

- 看到名字像就选，没读源码，结果动作阶段对不上镜头。→ 先 `show.mjs`。
- 把整片塞进一个组合片段。→ 一镜一个动效，组合只用于一整段连续画面。
- 镜头比动效短太多，动作被截断。→ `check` 会报错，加长镜头或换更短的动效。
- 写完计划就宣布完成。→ 计划通过只说明结构完整，画面好不好要渲染后实际看。
- 把检索排名当作理由。→ 检索只给线索，理由必须来自镜头的“起始到结束”。
