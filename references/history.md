# 历史来源与维护

历史页签已下线，当前没有可播放历史配方。已迁入的动作、插画和组合从正式目录使用；已迁入的旧书签跳到对应正式条目，其余失效书签回到默认动作。检索候选使用 `node scripts/match.mjs "需求原话"`，不依赖本机原作工程。

## 保留什么

历史审查的权威文件位于技能根目录的 `../../state/wise-motion/history/`：`source-snapshot.json` 保存原始记录，`source-evidence.json` 保存源码依据，`crosswalk.json` 保存逐条对应与修正，`review.md` 是生成的审查报告。原工程、原素材与许可保持原位，不因页面入口下线而删除。

正式条目的旧名称与跳转以 `catalog/registry.json` 为准。需要追溯时，按条目的来源路径和历史记录中的迁移依据读取对应原作，不把旧案例的画幅、时长或专用逻辑当作通用默认值。动作结构等效、只提取组成动作、保留原作专用逻辑是不同结论，不据此声称整段原作已完成通用封装。

## 维护与验证

日常 `npm run build`、`npm run check` 和词语检索只使用技能目录内的文件，不读取或改写私有历史档案。仅在修改历史来源记录后运行：

```sh
npm run build:history
npm run check:history
```

前者同步 `catalog/history-data.js` 与私有状态目录中的 `review.md`，后者只读核对。历史编译拒绝恢复可播放历史条目。生成数据不是第二份手工维护的权威来源。

完整 `npm test` 保留历史迁移依据与兼容接口检查，需要私有状态目录及相关原作文件；移到没有这些档案的机器时，用日常检查验证正式目录，不能宣称历史回归也已通过。历史播放兼容程序及其测试仍有调用关系，本次不按文件名成组删除。它们不代表目录中仍有历史页签。

历史变更流水和旧文档留在私有维护记录，技能正文只保留当前使用边界。实际目录体验按 [人工验收步骤](../tests/manual.md) 检查；自动检查不代替真实浏览器体验。
