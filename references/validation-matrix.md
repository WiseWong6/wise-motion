# Wise 视频验证矩阵

## 原则

- 自动检查证明结构和可重建性，不替代用户真实观看。
- 先按当前任务选择参考、静态页、交互动效或视频检查。连续视频规则不强加给用户明确要求的停留或循环；目录示例按自己的播放接口检查。
- 截图、抽帧联系表和视觉复核按用户授权执行；已请求成片时完成必要检查后渲染。问题定位优先用已有画面、口述和数值证据。
- 视觉争议先取证：用户截图/口述/离线数值断言先行，无画面证据不连续调参；检查项数不构成视觉正确证据。
- 清晰度疑点先查源素材像素、内部画布尺寸、最大显示尺寸与缩放裁切链路；不把高分辨率容器或重新放大导出当成修复证据。确需观看取证时按当前授权检查代表片段，不固定要求 4K 或 2K；默认不新增截图或耗时视觉自检。
- 每次验证报告实际命令、结果、绝对路径、失败信号和临时产物。
- 验证产生的临时目录用 `mktemp`，完成后清理；仅停止本次创建且不再需要的开发服务器和浏览器进程。

## 检查对象

下列合同级别与 HyperFrames 命令只适用于对应工程。静态页检查画布与动效接口，Remotion 或逐帧装配工程检查自己的时间表、资源与输出，不强套合同或 HyperFrames 命令。执行仅覆盖已授权范围。

## Level 1：contract

适用于初始化、修改前和小范围编辑后：

1. 先确认检查对象是当前交付版。只对拥有该版画面源的 `wise-video.json` 运行 `wise_video_contract.py validate --level contract`。独立旧剪辑没有自身合同时，对剪辑目录运行 `--legacy-ok`，并另外核对时间表、配音哈希、预览入口和成片元数据；上层原片合同失败另行报告，不冒充本片结果。
2. 检查 authority 路径、时间锁、cue/object 引用、locked asset 哈希、baseline 和变体声明。
3. 运行 HyperFrames `check` 的项目命令；不得因为合同通过就宣称画面通过。
4. Git 只允许出现当前任务范围；用户已有修改不得被暂存、覆盖或重排。

失败信号：缺 authority、锁定时间无源、未知 cue/object、哈希变化、基线路径被复用、变体选择器非法。

## Level 2：preview

适用于影响节奏、镜头、字幕、持续主体或视觉的修改：

1. 先通过 contract。
2. 检查 Storyboard 中被引用 scene 都有 `motion_intent`，或帧工程有对应动作计划；内容按 `wise-motion-dna.md` 写清当前唯一强化主体、动作配合与下一段承接，不能只填“淡入”或“做得好看”。
3. 运行 HyperFrames check，并只检查受影响 scene/cue/切点。
4. 配音工程重跑语音-节奏验证链（词级对齐 → 音频构建 → check-pacing → check-audio → 逐句字速审计）：音轨无异常长停顿时核对原音采样连续保留；剪长停顿时核对保留区间无缺口、无重复和句口波形。慢句、句尾吞字、气口外长停顿在这一级拦下；浏览器主观听感仍留给用户。
5. 有声教程数值抽样：可先建立待解释对象，再随词点改变状态，不提前揭示后句结论；是否从空白建立由叙事决定，持续主体与真实原件按交接或阅读目的保留；字幕在句初不可整句可见，随后按字点单调显现且保持一行居中；普通讲解句的前、中、后段核对与内容关联的状态变化或已声明的结果阅读任务。真实模板/原件保持文字可读，按解释或阅读职责检查，不以静止直接判败，也不豁免内容与交接检查。倒序和乱序拖动应得到相同状态。
6. 排版按每句旁白结束前的实际呈现状态检查，不能只测内容全部出现后的终态；用实际字形与图形边界核对：两列内容连同标签计算左右与列间留白，成对图文核对纵向中心，比较标题、主体、当前说明、字幕之间及主体内部的空隙。保留已确认尺寸，先调整间距。安全区无越界、无碰撞不能单独判定空间利用合格；用户明确要求全片检查时覆盖各镜头的逐句状态和切换点。
   对连续累积内容，逐句列出“此时已出现/尚未出现”的元素，分别验起声、关键词、句中、收声前和切页前；特别量后续结果尚未揭示时的空白。核对图标、标题、说明和字幕的真实可见边界，记录整改前后的坐标与尺寸，防止用放大伪装间距调整。具体逐项清单见 `narrated-tutorial-review.md`。
   案例展示同时核对：当前需阅读的说明是否挤占主体、缩略网格是否误作效果证明、宽高是否等比、裁切是否保留动作路径与落点、源与中间画布是否满足最大显示尺寸。比例、像素和边界数值通过只能证明相关技术条件；案例是否看得清、密度是否合适仍需真实观看证据，未观看就列为未验证。
   若用户提供截图，先核对截图所播版本、时间点和当前源/导出文件是否一致；修改命中哪个状态、未覆盖哪个状态应明确说出。
7. 连续性检查覆盖受影响播放区间及前后交接，含句间、阅读、转场与结尾，按 `wise-motion-dna.md` 判断：
   - 先区分主体事件与阅读辅助：主体发生什么变化、说明什么。核对起势、关键改变、落点与阅读／交接是否可辨；对比是否先建立参照，操作是否先有目标再有反馈。镜头长短是否符合识别、比较或操作任务，段落是否在理解负担增加时留出时间；具体方法见 [导演设计方法](director-design.md)。动作覆盖、绘图次数或“无空窗”只证明安排了变化；仅有辅助线或标签运动而主体缺席，仍是表达不足。
   - 按输出帧率扫描非字幕叙事层的相邻帧及动作状态，列出连续重复帧、空白等待或动作全部结束的区间；先将这些区间列为待核对项：有明确阅读对象、起止与后续交接的结果阅读窗可以保留；无内容等待才需修正。检查阈值依画幅和有效可见运动声明，不用压缩噪声、背景微动或只动字幕消除失败信号。
   - 对每个连续运动边界检查前后位置、方向、速度及旋转趋势；参数或渲染坐标可取样时记录实值与时间，区分相机运动和物体运动。焦点交接核对前后强化主体与配角状态，同一时刻多个主体同时放大、发光或强对比应拦下。
   - 有光影与声音时核对实体、光源、接触影和真实接触时刻；无音频工程执行同一视觉判据。数值或像素扫描只能提供候选与覆盖证据，仍须核对变化是否推动当前叙事。
   - 有完整区间数据才报告该区间已检查；只有抽样、仅检查脚本语法或缺少可用取样接口时，明确未验证连续性与唯一主体，不冒充通过。浏览器、截图与渲染仍按当前任务授权执行。
8. 向用户提供 Studio/预览地址和具名时间点；用户未授权渲染时等待批准。已在当前任务明确要求成片的，完成验证后直接渲染。

用户要求“全片”时，上述检查不可退化为受影响片段抽样。建立覆盖表：所有镜头、所有句子的起声／关键词／句中／收声前／切页前，以及每个切点前后一帧；把实际检查时间、来源、空间或节奏结论逐项记下。先检查真实交付成片；没有成片时检查同源预览并写明差别。量化留白、对齐、字号保护和越界结果时，同时看画面是否随语音合理变化，避免用终态掩盖过程中的空白。覆盖不足时报告具体未查范围，不给整片通过结论。

失败信号：动作与词点错位、字幕整句闪现、播放区间出现无阅读或叙事依据的停顿、新教学内容未按词点建立且无阅读或连续性依据、持续对象缺交接、动量无故归零或跳变、连续动作被切断、多个主体同时抢焦点、只有装饰层或字幕运动而叙事停住、阅读窗不足、说明挤占案例、缩略图无法展示所声称的效果、主体意外拉伸或关键动作被裁掉、低清源被放大且未说明限制、转场遮掉关键落点、同等权重列的留白明显失衡、成对图文未对齐、大片空白与局部拥挤并存、中间呈现态只用终态代验、无目的的语音停顿或短词速率突变、结尾内容提前揭示、无来源的新增文案或数据、未声明的变体差异、字速慢句未修复未豁免、字幕与旁白文本不一致。

## Level 3：delivery

仅在用户已明确授权成片后：

1. 按真实授权更新记录：预览已经验收才写 `approved`；用户明确要求直接成片、未验预览时写 `skipped` 并在 `BRIEF.md` Notes 记录跳过依据；渲染已授权才写 `renderAuthorized: true`，不得伪填预览批准。
2. 渲染前运行 `validate --level delivery` 检查授权、基线及默认构建；该命令不验成片，导出后仍须执行文件级检查。
3. 执行 HyperFrames render；生成新命名成片，不覆盖批准基线。
4. 完整解码成片，核对分辨率、帧率、时长、音轨、峰值和 SHA-256。
5. 在新成片复核受影响完整区间的停顿、动量与唯一强化主体，检查方法同预览级别；变体同时检查共享段一致性和允许差异。
6. 配音工程交付前抽听替换句、改词句，确认音文一致；标点或显示形式变化核对底稿、字幕与旁白准备脚本；实际改词必须重合成受影响语音。
7. 根据受影响逐句记录核对源文件、预览与导出版本；至少回查用户指出状态的前一句、该句五个状态和下一句切点。若用户要求“全片”，提交有数量和时间点的逐镜逐句覆盖表，而非抽几个最终画面。客观检查和人工观看分别报告；没有人工观看不得声称观感已验收。导出后源文件若变了，必须重新导出或将现有成片标为旧版。
8. 按当前交付约定核对封面：约定首帧兼作封面时比较一致性；需要文件封面且容器与平台支持时核对 attached_pic；所需平台比例独立图齐备；生图封面核对代码补字的数字与名称逐处无误。
9. 仅在用户已授权删除时，删除旧成片前留存清单（路径＋字节数 json），工程素材视频不动；数据分数、技术口径、字体与素材授权等内容级核查与文件级检查分别报告，未核查不交付。

失败信号：未经渲染授权、active 非 default、成片无法完整解码、共享段变化、音频或字幕未同步、抽听发现吞字或语速异常、缺少约定封面产物、旧成片删除无清单、必需的数据或授权核查未完成却声称已验收。

## 典型边界检查

| 场景 | 必须证明 | 失败信号 |
| --- | --- | --- |
| 持续主体跨镜 | 同一对象身份与运动状态接续 | 位置、缩放、旋转或速度跳变 |
| 词点触发视觉变化 | 真实语音驱动画面，锁定语音保持不变 | 用估计秒数代替实测，或私自改语音 |
| 多个结尾变体 | 只改变声明内容，保护基线并恢复默认构建 | 共享段变化或非默认构建残留 |

## Remotion 与保真接入

- 新动效核对当前帧是否为唯一时间来源，随机结果固定；预览和导出共用组件。保留原动作自身的帧格，测试顺序、倒序、乱序、重复取样及同帧同画。
- 旧绘制迁移先记录原版文件校验值与条目／变体覆盖表。检查首帧、中间帧、末帧和阶段交接；循环至少覆盖两个周期，核对只在首轮出现的入场。倍速、缓动、主题、专项参数和变体切换按真实接口检查。
- 检查字体、图片、字形准备成功后才呈现对应帧；加载失败应中止导出并保留原因。覆盖异步结果迟到、销毁后完成、多实例、反复挂载、资源释放、不同时间段串联与叠放。
- 画面对比在同一浏览器版本、字体、画幅与像素密度下取相同时刻；记录目录时间与原设计时间的映射。像素相同可以自动通过；非零差异必须复核，只容许有证据的抗锯齿等绘制误差，构图、字体、材质、光照、轨迹和节奏变化必须修复，不能放宽阈值掩盖。截图和视觉复核仍按该次授权执行。
- 实际导出代表效果和组合短片，完整解码，核对帧率、时长、空白、闪烁和结尾；检查原逐格效果的重复帧节奏，不能误判为待消除的停顿。复制结果须放到独立工程运行，覆盖绘制依赖、字体、图片和素材根路径。
- 目录预览、相关动作弹窗、拆解、缩略图和复制分别检查；原版保护校验值应不变。只有全部目标条目及变体都有记录、差异已解决，才可报告全量迁移完成；技术验证、代理视觉复核和用户确认分别陈述。

## Skill 自身验收

```bash
python3 scripts/verify_project_skills.py --repo-root .
python3 scripts/verify_project_skills.py --repo-root <wise-video绝对路径>
```

规则分支推演至少覆盖以下输入；推演与结构检查不证明新会话实际加载或真实视频任务成功：

- “调整字幕位置”：Director 可参与合同保护，Disney 不加载。
- “检查/渲染已有工程”：只执行指定操作，Disney 不加载。
- “卡片回弹轻飘、动作机械”：当前项目有可用入口时按需读取 Disney，选择 1–3 条原则并输出 phase table；其他场景用本技能动作方法继续，不自动安装或迁入第三方代码。
- 仓库外任务：只有用户主动调用本技能才进入导演流程，不自动加载旧项目的第三方技能；工程规则按当前项目判断。

- “新做一段动效／新视频”：动效使用 Remotion，目录界面、静态画布和普通网页不因此换技术。
- “保留效果迁移旧动效”：保留原绘制与运动公式，在独立副本接入帧并做保真验收；未通过不声称完成。
- “已有 HyperFrames／HTML 视频修字幕”：沿用原工程，不自动迁移或新建 Remotion 工程。
- “已有 Remotion 片改一幕”：保留帧表与原栈，不强建 HyperFrames 合同。
- “直接给成片，跳过预览”：保留真实授权依据，合同记 `skipped`，必要检查后渲染，不伪填 `approved`。
- “无旁白 HyperFrames 片”：字幕可省，工程仍按自己的 HyperFrames 合同检查。

- “阅读页停几秒、背景循环”：先区分用户明确要停留还是想解决阅读不足。明确要求停留时按其要求保留并检查可读性；连续视频只要求便于阅读、未要求静止时，按阅读任务安排稳定结果窗或解释性推进，写清结束与交接，不用无内容等待或装饰循环代替叙事。
- “一组卡片一起进场”：维持一致节奏，以唯一主体的发起、配角回应和焦点接管组织动作，不同步强化所有卡片。
- “连续对象跨两镜”：核对位置与速度等运动状态衔接，不为新镜重置归零；只抽查首末帧不能证明中间无停顿。

## 设计分支核对

- “让零散信息形成一个观点”：从表达关系设计，不依赖动作名称命中。
- “库里的动效很好，但想更有张力”：允许改良构图、阶段、节奏与衔接，不机械照抄。
- “没找到一样的，直接发挥”：继续原创或跨类重组，不把检索空结果当阻塞。
- “随机组合，但不要停顿和翻面”：探索新搭配并保留用户禁项；采用方案固定，不在播放时重新随机。
