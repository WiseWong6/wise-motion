# Wise Motion 验证矩阵

## 按交付选择检查

| 当前交付 | 检查范围 |
| --- | --- |
| 参考或方案 | 需求、候选、源码依据和适用边界；未实现部分标为方案 |
| 静态画布或普通网页 | 内容、布局、资源和实际交互；无服务器依赖时本地直开 |
| 新动效或 Remotion 视频 | 分镜、独立组件、帧取样、整合边界及所需成片检查 |
| 已有其他技术的工程 | 使用原工程的时间表、检查与导出入口 |
| HyperFrames 工程 | 另按 [制作保护约定](production-contract.md) 检查合同与授权 |
| 参考目录或旧绘制迁移 | 按实际改动检查目录功能或保真接入，体验见 [人工验收步骤](../tests/manual.md) |

## 通用原则

- 自动检查证明所覆盖的结构、数据和时间关系，观感验收需要真实观看。分别报告实际命令、结果、绝对路径及未验证项。
- 默认不截图、不抽帧联系表、不做耗时视觉自检。浏览器操作和视觉复核按当前授权执行；已请求成片时完成必要检查后渲染。
- 先核对当前预览、画面源、音频、时间表和成片是否对应同一交付版本。视觉争议优先使用用户画面、口述和数值证据，无画面依据不连续调参。
- 检查覆盖本次改动及相关边界；必要检查通过且没有疑点后停止。已有修改保持不变。临时目录用 `mktemp`，清理本次无关产物和不再需要的辅助进程，保留验收文件。

## 单项开发与整合

- 依据：按 [导演设计方法](director-design.md) 核对实现分类。复用项有已读源码、参数和放置时段；微调与原创有开发前写入的当前提示词及对应实现。
- 分镜：运行 `plan.mjs check`，处理错误与提醒。字段正确只证明声明有效，不能证明已读源码、动作适合或实现完成。缺少独立组件的镜头仍为待完成项。
- 独立组件：核对组件文件、导出名称与装配引用。两个镜头修改同一参考时各自生效，公共素材保持不变；修改计划并重新装配后，独立实现及引用仍保留。上层透明检查只适用于已审计且未改绘制的目录组件。
- 单项结果：检查素材准备、初态、关键变化、终态和时间边界；支持取样时检查重复、倒序与乱序定位。当前项通过必要检查后再开发下一项，完成记录与实际顺序一致。
- 整合结果：列出所有相邻交接，核对切点前后状态，交叠转场覆盖整个交叠区间，循环覆盖连接处。检查对象身份、位置、方向、必要的速度连续、层级、透明度、焦点，以及字幕和声音的承接。每处记录取样位置、依据、结果及未验证范围；单项通过不代表整合通过。

## Remotion 与保真接入

- 当前帧是画面的唯一时间来源，随机结果固定，预览和导出共用组件。保留原动作的帧格，核对顺序、倒序、乱序及同帧重复取样。
- 字体、图片、字形准备完成后才绘制；失败应中止导出。检查异步结果迟到、销毁后完成、多实例、反复挂载、资源释放、不同时间段串联与叠放。
- 迁移前保留原版校验值和条目、变体覆盖表。对照首帧、中间帧、末帧及阶段交接；循环至少覆盖两个周期。倍速、缓动、主题和专项参数按真实接口核对。
- 获准画面对比时，使用同一浏览器版本、字体、画幅、像素密度及相同时刻，记录目录时间与原设计时间的映射。非零差异须复核；仅容许有证据的抗锯齿等绘制误差，构图、材质、光照、轨迹和节奏差异不能靠放宽阈值通过。
- 复制产物在独立工程核对依赖、字体、图片、素材路径和组件装配；需成片验收时导出代表效果与组合短片，完整解码并检查帧率、时长、空白、闪烁和结尾。原逐格效果的重复帧不直接视为故障。
- 目录改动分别覆盖预览、相关动作、拆解、缩略图与复制。仅在全部目标条目及变体都有证据、差异已解决后，报告全量迁移完成；技术检查、代理视觉复核和用户确认分别说明。

## 预览、排版与连续性

1. 运行当前工程的必要结构检查。动作计划写清主体、起止状态、结果阅读任务及下一镜交接；设计判断按 [视觉与动作方法](wise-motion-dna.md) 核对。
2. 检查实际呈现过程中的字形和图形边界，不只量内容全部出现后的终态。对照左右与列间留白、成对图文中心、标题与主体及字幕的间距。保留已确认尺寸，安全区无越界不能代替间距与观感判断。
3. 案例需有看清关键动作的尺寸和时间。核对原始比例、裁切范围、运动路径与落点；清晰度疑点先查源素材像素、内部画布与最大显示尺寸，计入缩放和裁切。高分辨率容器或放大缓存不能证明素材足够清晰。
4. 连续视频检查受影响完整区间及前后交接，含阅读、转场与结尾。按输出帧率扫描非字幕叙事层，列出连续重复帧、空白等待和动作全部结束的区间，再核对其叙事职责。有明确对象、起止和交接的结果阅读窗可以保留；用户明确要求的停留或循环按其目的检查。
5. 连续运动边界核对位置、方向、速度及旋转趋势，区分相机与物体运动；有取样接口时记录实值与时间。焦点交接核对前后强化主体，光影与声音核对实体、光源和接触时刻。装饰微动、压缩噪声或只动字幕不能掩盖无内容等待。
6. 有完整区间数据才报告区间已检查；抽样或缺少取样接口时说明连续性与焦点检查的缺口。数值通过不等于案例可读、密度合适或观感已验收。提供可打开的预览路径或地址及具名时间点。

失败信号包括：意外空白、重影、跳变、动作截断、持续对象丢失、无依据停顿、多个主体抢焦点、阅读不足、说明挤占案例、拉伸或裁掉关键动作、低清素材被放大且未说明限制。

## 有旁白的作品

- 使用工程已有的词级对齐、音频构建、节奏与音频检查链。核对原声连续性、整句及短词字速、气口和尾音；裁剪长停顿时检查保留区间无遗漏、重复或乱序。
- 字幕按真实词点单调显现，遵循已确认布局；核对旁白、字幕和主体变化是否表达同一内容，不提前揭示后句结论。持续主体和真实原件按交接或阅读任务保留，静止本身不判失败。
- 逐句状态、空间记录及声音核对按 [教程复查](narrated-tutorial-review.md) 执行。用户指出的句子连同前后句检查；要求全片时覆盖所有镜头、每句起声／关键词／句中／收声前／切页前及每个切点前后一帧，记录实查时间、来源和未覆盖项。
- 优先检查当前交付成片；只有同源预览时说明差别。五个状态抽样不能代替其间完整区间检查，无声画面不能证明语音已验收。

## 成片交付

1. 已在当前任务要求成片时，按工程导出命令执行；使用新文件名并保护已确认基线。涉及合同、锁定资产和变体时执行工程自身的保护检查。
2. 完整解码成片，核对分辨率、帧率、时长、音轨、峰值和文件校验值；复查受影响完整区间的连续性和焦点。变体核对共享段一致性及允许差异。
3. 配音工程抽听替换句、改词句，确认音文一致；实际词句变化须重合成受影响语音并更新字幕和动作。显示形式变化也核对底稿与旁白准备文本。
4. 对照实际逐句记录核对源、预览和成片版本。源文件变化后重新导出，或明确现有成片是旧版。全片检查提交数量与时间点覆盖记录；未观看不宣称观感已验收。
5. 按交付约定核对封面：首帧兼作封面时比较一致性，需要文件封面时核对容器与平台支持及 `attached_pic`，独立比例图按请求准备，生成图中的数字和名称逐处复核。
6. 数据、技术口径、字体和素材权利分别核对，必需检查缺失时说明阻塞。删除旧产物须有授权，先留路径及字节数清单，保护源素材。

## 技能自身验收

修改规则或入口后，在技能实际目录运行：

```sh
python3 scripts/verify_project_skills.py --repo-root .
```

涉及 wise-video 项目入口时，再将 `--repo-root` 指向该项目实际目录。规则推演按变更选择相关输入；推演和结构检查不证明新会话加载或真实视频任务成功。

| 输入 | 应走的分支 |
| --- | --- |
| 只换文案或使用已有速度参数 | 复用；改布局代码才进入微调，重新实现进入原创 |
| 两镜分别微调同一参考 | 独立组件分别生效，重新装配保留实现 |
| 调整字幕、检查或渲染已有工程 | 只回到相关阶段，沿用原栈、时间表和授权 |
| 新做动效或视频 | 默认 Remotion；静态画布和普通网页按自身需要选技术 |
| 保留效果迁移旧动效 | 独立副本保真接入，未通过不声称完成 |
| 直接要成片，跳过预览 | 必要检查后导出；有合同的工程如实记录授权 |
| 卡片回弹轻飘、动作机械 | 按阶段方法判断是否需要且可读取 Disney 原则；不自动安装 |
| 阅读页停几秒、背景循环 | 保留明确要求，检查阅读任务与交接 |
| 一组卡片进入或同一对象跨镜 | 按语义主体安排焦点，核对因果与运动状态接续 |
| 没找到参考、改良参考或随机组合 | 按导演设计方法继续，保留禁项并固定采用方案 |

仓库外调用按当前项目规则执行，不自动加载旧项目的第三方技能；HyperFrames 有无旁白均使用自己的合同。
