# 从意图到画面与动作

本方法用于导演设计。检索找到的是线索，设计可以改良、重组或原创，不以是否命中本地库决定能否继续。

## 理解用户真正要表达什么

先回答：给谁看，在什么场景看，希望对方看懂什么、注意什么或做什么。再提取用户已指定的对象、内容、比例、叙事关系和禁项。模糊感受需要转成可观察的画面，不能把“自然”“高级”“有生命力”机械翻译成某个特效。

只有用户明确指定的要求和当前作品已锁定的内容才是边界。参考里的示例对象、默认时长、颜色、动作保留项和旧作品主题都是参考属性；可以改动，但须说清差异。用户只给目的时，动作结构本身也可设计。

## 先设计，再借鉴

- 核心信息与层级：这一段让人看懂什么，当前唯一强化主体是谁。把整镜要讲的信息分配到先后状态，不一次铺满；当前理解用不到的说明后置或删去，不靠缩小字号和案例容纳更多内容。
- 案例展示：先区分“看有哪些”和“看效果如何”。缩略网格可表达数量或筛选；证明效果时让当前案例成为主画面，给出看清关键动作和落点的尺寸与时间。并列只用于必要比较；若细节看不清就顺序展示，不堆缩略卡片再贴“效果好”的标签。
- 图形表达：先确定“主体—原状态—触发—新状态—含义”。用形态、数量、空间、功能或对象关系演出变化；图标旁放文字、卡片换句子本身不等于解释成立。
- 构图与观看路径：主体放哪里，视线从哪里进入，怎样转向结果或下一段。
- 视觉方向：字体、色彩、形状、材质与信息密度共同服务内容，保持整段一致。
- 动作与时间：主体发起、配角回应、焦点交接；阅读段降低信息更新速度，保持文字清楚。
- 实现边界：哪些素材可直接使用，哪些需要生成；动效有哪些可用源码，哪些需要改造或新写。大改先做代表性小样，检查方式与请求相称。

有旁白时，字幕承载完整句子；画面文字保留必要名称、数值和短标签。写计划时暂去字幕与解释标签，推演观众还能看懂什么；若只剩文字出现、框线增长或装饰移动，重新设计主体。此推演无需额外截图或浏览器操作。

有故事板或动作计划就在原文件记录，不另外复制文案或时间表。单个参考请求可以直接在回复中说明，无需建立制作工程。

## 给镜头分配任务与时长

在已有故事板或动作计划为每镜写一行：**看谁 → 从什么状态变成什么状态 → 观众由此理解什么 → 落点让观众看清什么、怎样交给下一镜**。同时注明主体占画面的范围、动作所需留白和必要标签；已有字段能表达就沿用，不新建一套表。

- **短镜头用于识别与串联。** 已熟悉的对象、一个概念或一个明确动作可快速带过；若要辨认新对象、读新文字并理解新关系，就减少信息或延长，不按一句话固定切一镜。
- **中等镜头用于变化与比较。** 先建立参照，再改变一个关键关系，最后让结果可被看清。两组对象可以同时留在画面，强化顺序要清楚，不让入场、数值增长和结论同时争夺注意。
- **长演示用于操作链。** 用“目标出现 → 操作发生 → 结果反馈”组织内部小节；镜头长不等于主体一直匀速移动。每一步让观众找到操作位置并看到反馈，再进入下一步。
- **段落速度随理解负担改变。** 快速串联建立范围，遇到新关系、关键对比或实际操作就放慢，结果明确后再提速。检查连续几镜是否一直同样快、同样满；改变的是信息推进速度，不是把所有动画统一倍速。

短、中、长是当前片内的相对关系，没有通用秒数或固定比例。参考的画风、片长、镜头数、绘制技术和平台标识处理不是方法本身；只迁移已经用原画面证实的表达关系。

## 选择并制作画面素材

进入制作时，将素材生产与动效参考分开决定。具象插画、场景、材质或情绪表达优先使用当前宿主可用且获准的生图能力，先产出可直接用于作品的实际画面，再据此安排动作与分层。几何图形、精确数据和已有可编辑原件按任务采用代码或原素材，不默认把“图形化”理解为代码画图，也不要求所有任务生图。用户明确选择生图时直接执行，不能以代码示意或占位图充当生成素材；能力不可用时说明阻塞。

## 语义借鉴

先把内容理解为变化关系，再找动作线索。例如：

| 想表达的关系 | 可借鉴的动作思路 | 可改良或发散的方向 |
| --- | --- | --- |
| 零散信息形成共识 | 汇聚、连接、重组 | 卡片先保留差异，再由共同要素接成一条线；也可不用卡片，改成文字关系 |
| 从复杂走向清晰 | 分层、聚焦、逐项揭示 | 让冲突内容退出、保留主线，或让遮挡关系改变；不必须套聚焦放大 |
| 持续增长 | 数量递增、结构生长、路径延伸 | 增长可以由结构累积演出，数字只作结果回应 |
| 一个动作带来响应 | 跟随、传播、接触、涟漪 | 回应发生在真实触发之后，延迟与强度按对象设计 |
| 观点反转或关系改变 | 翻面、换形、重排、焦点交接 | 借“前后状态”的关系，未必使用物理翻面 |

这些是示例思路，不是关键词到动作的固定映射。同一个动作可以表达不同含义，同一含义也可用不同动作。按目的、因果、顺序、循环、可读性和节奏解释借鉴理由。

先读 [轻量索引](index.md)，选定后读具体说明与真实源码。`scripts/match.mjs` 只按词语和别名辅助检索；无结果不代表语义没有关联，更不代表设计不能做。历史案例按 [历史使用方法](history.md) 核对依赖与实际实现，不能把一个子动作宣称为整个原作。

## 源码依据

选中参考后，必须实际打开当前可用的真实源码，读清绘制入口、运动公式、缓动、时间换算、关键参数和必要素材依赖。在原故事板或动作计划中记录源码路径、使用的函数或组件、保留的实现与拟改部分；索引、名称、缩略图、复制提示词和历史描述都不能代替读源码。源码无法读取或缺少关键依赖时说明缺口，不凭印象补写后声称复用；用户要求复用该项时，先取得源码或确认改为原创。

复用默认保留选中效果的实际画面与运动逻辑，允许在任务范围内微调。改变核心动作关系、跨类重组或重新实现应明确标为重新创作，不把它当作原效果的等效复刻。

## 开发提示词内容

提示词写在动作计划或故事板的对应动效下，源码依据另列。每段应能直接指导本项开发，至少包含：

- 主体、构图、初始状态以及要表达的变化。
- 原效果哪些保持不变、此次只改什么；原创部分明确标出。
- 触发、起势、推进、落点、结果停留与退场，写明方向、节奏和关键参数；时间引用工程现有时间表。
- 与前后动效如何衔接，以及必须避免的跳变、遮挡或内容丢失。
- 本动效的完成判据：怎样核对实现符合提示词、原实现和此次改动范围。

用可观察的动作和参数代替“照着做”“更高级”“优化一下”。

## 改良与发散

匹配到时以已读源码为基准，按表达需要选择微调或重组。没有匹配时，从内容变化、现实运动、观看路径和相反状态发散，提出可观察、可实现的方案；无需为“库里没有”强制联网。

参考自身的结构可改，用户明确要求的结构要保留。例如双排反向持续滚动可以更换对象、变节奏、加入有因果的环境响应，但不能悄悄变为单张轮播。用户只说“丰富而有序”时，轮播、连续流动或逐项聚合都可探索，再选最能表达目的的一种。

复用参考源码时先核对程序与素材许可；采用新实现时说明借鉴关系，不伪称原参考完全等效。需要核实技术事实或外部来源时才定向查证。

## 随机组合与收敛

随机是寻找意外搭配的方法，组合仍要有表达理由。可以从不同类别、未命中的参考、现实类比和原创动作中取用，不限于检索最高分，也不要求每层都取自动效库。

1. 根据当前目的确定可变化的部分：主体动作、配角回应、过渡、构图或材质；用户指定和已锁定部分不参与随机变化。
2. 产生少量有差别的草案。可顺序接续、让一个动作触发另一个、让同一对象接管下一动作，或借不同材质重新解释同一变化；不要默认把多个强效果同时叠满。
3. 淘汰含义错误、违反禁项、因果不成立、抢焦点、破坏阅读或实现依据不足的组合。匹配分数仅帮助查找，不能代替设计判断。
4. 选一个推荐并解释目的、变化过程和借鉴关系。用户明确要多个方案时再并列交付，不默认让用户做大量选择。
5. 在现有动作计划记录采用的组合、参数与版本；若生成过程实际用到随机数，固定种子或保存生成结果。同一时刻重复取样得到同一画面，重播、拖动与导出不重新抽取。

## 简明交接

设计说明包括：目标和核心信息、主体与构图、动作阶段、节奏、触发与交接、借鉴与改良、原创部分、用户约束和关键假设。附真实参考与源码路径；尚未实现的部分明确写为方案。参考请求到此完成，实现或视频请求按 [阶段制作方法](pipeline-methodology.md) 继续。
