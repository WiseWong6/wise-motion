# Remotion 制作与保真接入

仅在接入、维护目录的 Remotion 组件或明确授权迁移时读取。下列为既有实现的技术约定；整片创作与调用方技术选择自行决定。

## 组件约定

- 动效作为可组合的 React 组件交付，由 `useCurrentFrame()` 和 `useVideoConfig()` 取得帧号及帧率；位置、透明度、形状与材质变化都由当前帧和显式参数确定。秒数从帧率换算，禁止自由运行的计时器、真实时间或未固定的随机数参与最终画面。
- 在时间段中使用局部帧组织入场和退场，需要全片时间时显式传入。组件在多个位置、不同时间段或并行实例使用时不能共享可变画面状态。
- 预览与导出共用画面组件、帧表和素材。新增原创效果可采用 Remotion 自带插值与弹性计算；复用旧效果时不因更换工具顺手替换原曲线。
- 先从工程实际依赖与锁文件确认支持的接口；同组 Remotion 包保持版本一致。素材路径相对工程或显式素材根定位，不把个人绝对路径写进可复用组件。

官方依据：所有动效需同步当前帧，见 [第三方绘制接入](https://www.remotion.dev/docs/third-party)；局部帧与首末帧约定见 [当前帧接口](https://www.remotion.dev/docs/use-current-frame)。

## 保留原绘制

- 先记录原画面、运动公式、缓动、随机种子、字体、图片、画幅、内部像素尺寸和取样时钟。迁移的默认动作是保留实际绘制源码，由 Remotion 传入当前帧换算的时间；不根据文字说明重新模仿材质或光照。
- 保留目录时间到原设计时间的换算、独立动作在组合中的起点、循环累计时间和末尾停留。输出帧率默认每秒 60 帧，原片每秒 30 帧等逐格效果继续按自身帧格取样；不得额外平滑，也不把计时回调频率当作视频帧率。
- 保留源效果实际逻辑画板并等比缩放；640×360 仅适用于采用该画板的目录效果，不强加给其他素材。迁移保留原绘图分辨率与像素密度约定；换画幅不得拉伸填满或默认裁掉主体。迁移不附带重新排版、换字体、加滤镜或调锐度。
- 清晰度按最终画面中素材的最大显示像素尺寸核对，计入镜头放大与裁切；逻辑画板尺寸不等于绘图像素尺寸。原位图或中间画布不足时，优先从可编辑源按所需尺寸重绘或换用足够清晰的素材，保留原构图与动作；仅提高成片分辨率、放大低清缓存或加锐化不能补回细节。无法满足时说明限制，不宣称清晰度通过。
- 元数据与组件共用当前有效条目定义，支持条目、变体、速度、缓动、主题、素材根路径和既有专项参数；给出实际时长、画幅、循环信息及可运行用例。具体名称以交付工程真实导出为准，不能文档先宣称某个组件已存在。
- 翻页等交互在目录中可以保留；视频使用固定演示动作。真实鼠标、键盘和墙上时间不能成为导出条件。

## 准备、错误与释放

- 字体加载并确认、图片完成解码、字形与材质准备结束后才绘制对应帧。用当前版本支持的 Remotion 等待机制阻止导出提前截帧；成功必须与本次实例和当前请求对应，失败明确中止导出并记录原因。
- 不以占位图、后备字体或缺图画面冒充成功。组件卸载时取消或忽略迟到结果，释放画布、图形上下文、监听与计时资源；重复销毁安全，已经销毁的实例不能被准备完成回调复活。
- 预览的准备状态与导出等待分别处理；素材改变时重新确认准备完成。不能只等待页面首次加载就认为所有后续变体均已就绪。

官方等待机制及配对释放要求见 [等待与继续渲染](https://www.remotion.dev/docs/delay-render)，实现按工程已安装版本核对。

## 复用与交付

- 独立工程复制输出包含实际绘制代码与固定依赖；普通条目输出共享组件包的接入示例，真实绘制代码、字体、素材与许可随共享包提供。两者均说明依赖与用法，不依赖原机绝对路径；输出与预览使用同一条目、变体和参数。
- 在独立工程验证复制产物能准备素材、定位和导出；有复杂绘制时覆盖同帧重复、倒序、乱序、跨周期与多实例。
- 验证按 [验证矩阵](validation-matrix.md) 执行。迁移先保护原版并做代表效果对照，再覆盖全部条目和变体；检查通过前保持进行中状态。副本、报告和对照产物的位置留在本次任务记录，技能不保存试验路径。
- 无服务器依赖的目录继续直接打开；Remotion 工程的开发或导出确需服务时说明用途，复用已有进程并清理本次创建的临时服务。原目录技术说明见 [播放接口](runtime-interface.md)，目录登记见 [目录维护](catalog-maintenance.md)。
